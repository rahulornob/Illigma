# Phase 2 · Design systems (development log)

## Styles and variables

- **Format** (`packages/format/src/definitions.ts`, format 0, optional): `manifest.json` gains `styles` (PAINT, TEXT, EFFECT, GRID, kept in panel order, with folders from "/" names) and `variables` (`collections` with modes and a default mode, plus `variables` with `valuesByMode`, which may be aliases). Both are written only when the file has some, so older files stay byte-identical. Node fields: `fillStyleId`, `strokeStyleId`, `textStyleId`, `effectStyleId`, `gridStyleId`, `boundVariables` (`"cornerRadius"`, `"fills.0"`, …) and `explicitVariableModes`. Validation refuses alias loops, type mismatches and missing modes.
- **Core**: a new operation `{ op: "meta", key: "styles" | "variables", value, prev }` replaces a definition list as a whole. `Transaction.setMeta` sets it, and undo, redo and replay handle it like any other operation. `withDefinitions(inner)` resolves links into the plain fields in the same transaction (each node's mode comes from its nearest ancestor's explicit mode, else the collection default). A field edited by hand detaches its style or binding. Helpers live in `packages/core/src/styles/api.ts`.
- **Normalizer chain** (apps/web layout.ts): `withComponents(withDefinitions(layoutNormalizer))`.
- **UI**: the Style button on the Fill, Stroke, Typography and Effects cards; the Local styles card (when nothing is selected); the Variable modes and Variables (bindings) cards; the Variables manager (it takes the canvas area); and the colour picker's Variables tab. E2E: `apps/web/e2e/styles.mjs`.
- **Gaps**: no grid style button yet (grid styles exist in the format and resolve to `layoutGrids`). Number bindings go through the Variables card, not a hexagon in each field. Variable scopes and code syntax are not editable. No W3C or Tokens Studio import or export. Deleting a variable in use doesn't offer a replacement. Renaming collections and modes uses a prompt.

## Components, variants and instances (single file)

- **Format** (`packages/format/src/components.ts`): `componentId`, `overrides` (keyed by the sublayer's `mainId`, `""` = the instance itself) and `componentProperties` (values) on INSTANCE; `componentPropertyDefinitions` (BOOLEAN, TEXT, INSTANCE_SWAP, VARIANT) on COMPONENT / COMPONENT_SET; `componentPropertyReferences` (`visible`, `characters`, `mainComponent`) on layers inside a component; `mainId` on instance sublayers. Validated in `validate.ts`, described in `schema/node.v0.schema.json`. Optional fields: older files read unchanged.
- **Model choice: materialised instances.** An instance's children are stored nodes, a copy of the main component's subtree with stable ids of their own and `mainId` pointing at what they copy. Renderer, layout, hit testing, clipboard and export see ordinary children, so they needed no change.
- **Core** (`packages/core/src/components/`): `withComponents(next)` normalizer (wired before layout in `apps/web/src/editor/layout.ts`). In every edit: user edits to instance layers become overrides on the outermost instance (setting a value back to the main's removes it); instances of changed components are rebuilt from main + properties + overrides (nested instances first, then their component's instances, to a fixed point); layout runs, and layout changes to mains are propagated once more. All in the edit's transaction, so one undo restores exactly. Variant switches keep layer ids and overrides by matching layer-name paths. Commands: `createComponent` (a frame becomes a component, same id; other selections are wrapped in "Component N"), `combineAsVariants` ("Property 1=Default", "Property 1=Variant2" …), `addVariant`, `createInstance`, `detachInstance` (frame, same ids; nested instances become outermost with overrides carried over), `resetOverrides`, `setVariant`, `setInstanceProperty`, `addComponentProperty`.
- **UI** (`apps/web/src/editor/components/`): ⌥⌘K create component, ⌥⌘B detach, context menu (Create component, Combine as variants, Detach instance, Reset all changes); Assets tab next to Layers (search, grouped by page, drag to canvas or Enter / double-click to insert); Properties card for instances (main name, variant pickers, boolean switches, text, instance swap, Go to main component, Reset all changes, Detach), components (create visibility / text / swap property for a layer) and sets (variant properties, Add variant). Blue `type/component` token, no purple.
- **Tests:** `packages/core/src/components/components.test.ts` (12: propagation with overrides, add/remove layers, override removal, undo/redo exactness, detach, reset, nested instances, variants, properties, id stability); e2e `apps/web/e2e/components.mjs` (28 checks).
- **QC round 9:** recovery replays a frame → component (delete + create with the same ids) and skips an edit that deletes but can't apply in full; `wouldCreateCycle` refuses component cycles in every command (and sync stops on files that already have one); delete, duplicate, group and drops inside an instance are refused, paste with an instance selected goes beside it, and copies keep `mainId` only inside a pasted instance; copy-paste of a main pastes an instance in the same file and a new local component in another file (instances become frames there, since there are no libraries); cross-file paste brings the styles and variables it uses (`apps/web/src/editor/clip-defs.ts`: reuse when name and value match, add when missing, detach on a name clash). Tests: `packages/core/src/components/cycles.test.ts`, `apps/web/src/editor/clipboard-qc9.test.ts`, `files.test.ts`, e2e `recovery.mjs`.
- **Gaps:** libraries (publish / other files); adding layers inside an instance by script is not blocked (the UI refuses it); nested-instance swap by hand (only through an INSTANCE_SWAP property); property rename / delete UI; exposed nested properties; preferred values; variant grid auto-layout of sets; instance-level resize of a non-auto-layout instance records child moves as overrides; Figma design QA pass for the "14 · Components" screens not run (Figma not connected).
